# 互联网项目

-   互联网项目
    -   高并发, 流量大
    -   大用户群体
    -   海量数据
    -   要求高速, 稳定
    -   功能繁琐
    -   变更快
-   传统项目
    -   企业内部



## 目标

### 高性能

-   **响应时间**

    -   执行一个请求从开始到最后收到的响应数据所花费的总时间

-   **并发数**

    -   系统能同时处理的请求数
    -   **并发连接数** 客户端向服务器发送请求, 并建立起TCP连接, 每秒钟服务器连接的总TCP数
    -   **请求数** QPS(Query Per Second)  每秒多少请求
    -   **并发用户数** 单位时间内有多少用户

-   **吞吐量**

    -   单位时间内系统能处理的请求数量

    -   **QPS** 每秒查询数

    -   **TPS** Transactions Per Second 每秒事物数

        事物: 客户机向服务器发送请求然后服务器做出反应的过程

        客户机发送请求时开始计数, 收到服务器响应后结束计时, 以此来计算使用的时间和完成的事物个数

一次事物可能有多次连接+多次请求

一次连接可能有多次请求

QPS>=并发连接数>=TPS

### 高可用

稳定性

要求分布式, 集群

### 可伸缩

通过硬件的增加/减少, 提高/降低处理能力

加一台服务器轻轻松松, 一台服务器挂了, 没啥影响

对用户来说, 加没加服务器没啥明显坏处



### 高可拓展

系统耦合性低, 方便新增/移除的方式, 增加/减少新的功能/模块

### 安全性

随时提供网站安全访问和数据加密

安全存储策略等

### 敏捷性

随需求应变, 快速响应

## 集群和分布式

-   集群
    -   很多机器干**一样**的事情
-   分布式
    -   很多机器干不一样的事情
    -   合起来干一件大事



## 架构

单体机构->垂直架构->分布式架构->SOA架构->微服务架构

-   单体架构

-   垂直架构

    -   拆分成多个独立项目

    -   多个项目之间完全不进行交互

        为此, 重复功能变多

-   分布式架构

    -   将重复的功能组件抽取为独立项目
    -   其余项目调用, 依赖该项目
    -   实现了服务的共享和**调用**
    -   调用:RPC , 有Http Rest, Java RMI, WebService SOAP协议 , Hession等
    -   服务的提供方一旦发生变更, 所有的消费方都需要变更

-   SOA架构

    -   ESB 企业服务总线, 统一管理所有的项目, 以整理他们互相调用的关系

        服务交互和服务治理

-   微服务架构

    -   强调将**业务彻底组件和服务化**
    -   原有的单个业务系统会拆分为多个可以独立开发, 设计, 运行的小应用
    -   应用之间通过服务完成交互和集成
    -   服务实现组件化, 开发者可以自由选择开发技术, 也不需要协调其他团队
    -   服务之间一般使用Rest Api互相调用
    -   去中心化: 每个微服务有自己私有的数据库持久化业务数据
    -   自动化部署: 把应用拆分称为一个一个独立的单个服务, 方便自动发部署, 测试, 运维
