# 注册中心

## 概念

管理服务, 治理服务的技术

##原理

服务提供者

服务调用者

- 服务提供者在注册中心注册服务信息

    -   由于服务调用者和服务提供者的身份常常互换

        故所有服务启动后都应该去注册服务信息

    -   服务和注册中心形成**心跳续约**

        服务的**实例挂了咋办**捏? 

        每隔一段时间向注册中心发送请求报告

- 注册中心保有服务的**注册表**

    - **注册表**

        -   服务名
        -   提供功能
        -   IP名
        -   端口号

    - 监控服务的心跳

        不跳了? 

        -   从注册表剔除该服务实例
        -   向服务的调用者发送**推送变更**, 以防服务的调用者对宕机的实例发送请求

- 服务的调用者**订阅**注册中心的信息

    - 注册中心提供需要的服务的实例列表

    - 挑选需要的实例(**负载均衡**)

        负载均衡的几种算法见MyCat

    - 向选中的请求实例列表发送请求





## Eureka和Nacos对比

Nacos将实例分为临时实例(默认)和非临时实例

![image-20240503144715068](../../assert/Day03-%E6%B3%A8%E5%86%8C%E4%B8%AD%E5%BF%83/image-20240503144715068.png)

临时实例, 实例做心跳

非临时实例不心跳, Nacos主动发送请求查看非临时实例是否健康

服务宕机之后, Nacos直接删除临时实例, 不删除非临时实例, 等待直到非临时实例恢复

Eureka对服务发现, 服务消费者定时拉取

Nacos, 服务消费者定时拉取+Nacos主动推送更新

Eureka采用AP方式, Nacos集群默认采用AP方式, 集群中存在非临时实例时采用CP模式
