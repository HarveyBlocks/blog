# 垃圾回收算法

查看垃圾回收器日志

```shell
-verbose:gc
```

## 核心思想

1.  找到内存中存活的对象
2.  释放不再存货对象的内存, 使程序能再次利用这部分空间

## 常见的垃圾回收算法

-   标记-清除算法 Mark Sweep GC 1960 
-   复制算法 Copying GC 1963
-   标记-整理算法 Mark Compact GC
-   分代GC Gecerational GC

## 垃圾回收算法对主进程的影响

垃圾回收过程中会通过单独的GC线程来完成, 不管使用哪一种GC算法,都会有部分阶段需要停止所有的用户线程

停止的过程称为Stop The World (STW), 如果STW时间过长则会影响用户的体验

## 衡量垃圾回收算法

1.  吞吐量
    -   CPU用于执行用户代码的时间与CPU总执行时间的比值
    -   吞吐量越高, 垃圾回收效率越高
2.  最大暂停时间
    -   所有垃圾回收过程中STW时间的最大值
    -   最大暂停时间越短, 用户使用系统收到的影响越短
3.  堆使用效率
    -   对堆的使用方式不同
    -   标记-清除算法可以使用完整的堆内存
    -   复制算法会将堆内存一份为二, 每次只能使用一半内存

## 标记-清除算法

1.  标记阶段

    将所有存活的对象进行标记(可达性分析)

2.  清除阶段

    从内存中删除没有被标记的对象

### 优缺点

-   优点

    -   实现简单
    -   百分百的堆使用效率

-   缺点

    -   内存碎片化

    -   分配新内存速度慢, 需要维护一个空间空间的链表, 保存空闲碎片大小

        极可能遍历到链表最后才能获得合适的内存空间

## 复制算法

1.  准备两片空间From-To, 在对象分配时只能使用其中之一(From)
2.  对于存货的对象, 从From移到To
3.  互换两片空间的名字

### 优缺点

-   优点
    -   只需要遍历一次存货对象, 吞吐量高
    -   不会发生碎片化
-   缺点
    -   内存使用率低
    -   需要进行复制, 效率有部分减少

## 标记-整理算法

对标记-清理算法的内存空间碎片进行整理

1.  标记阶段

    将所有存活的对象进行标记(可达性分析)

2.  整理阶段

    将存货对象移动到堆的一端, 清理原来的内存空间

### 优缺点

-   优点

    -   内存使用效率高
    -   不会发生碎片化

-   缺点

    -   多次遍历, Lisp2需要对整个堆中的对象搜索3次, 整体性能不佳

        但还有Two-Finger, 表格算法, ImmixGC

## 分代GC

JDK8开启分代GC算法

```shell
-XX:+UseServialGC
```

### 内存划分

arthuas中`memory`查看得到`eden_space`, `survicor_space`, `tenured_gen`就是分代GC的有关内存区域

-   将内存分为年轻代(Young)和老年代(`tenured_gen`, 老年代)
-   存活时间长的对象从Young到Old
-   Young区
    -   Eden(伊甸园)区, 分配给新生成的对象
    -   S0 (Survivor)区和S1 区帮助复制算法, S0为From ,S1为To

-   系统中的大部分对象, 创建出来之后很快就可以被回收, 对于传统的项目, 每一次请求涉及的数据往往相互相互独立, 而哪些需要长时间存放的数据又会被存放在基于磁盘的数据库中
-   而系统中不变的对象, 例如Spring的Bean, 程序启动之后被创建, 后面也不会被销毁了
-   在虚拟机的默认设置中, 新生代大小远小于老年代的大小

### 算法流程

1.  创建的新对象放入Eden, 年龄设为0

2.  Eden区满, 触发年轻代GC(`Minor GC`/`Young GC`)

    1.  Minor GC将Eden中和S0中需要回收的对象回收, 把存活的对象放入S1区域, 存活对象年龄+1
    2.  互换S1, S0(互换From, To), 继续执行Step1
    3.  有一个对象, 年龄达到15(JVM可设置的最大值, 非默认值, 不同JVM不同而不同), 对象晋升到老年代

    1.  执行Minor GC, 执行了之后还不够, 放入老年代

3.  老年代存满, 执行MinorGC, 尝试放入年轻代

4.  年轻代依旧存满, 执行Full GC, 对整个堆进行垃圾回收, STW会比较久

5.  FullGC之后仍然无法申请内存, `OutOfMemoryError`
