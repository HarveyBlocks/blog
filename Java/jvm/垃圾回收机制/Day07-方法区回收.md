# 方法区回收

## 线程不共享的运行时数据区的GC

程序计数器, Java虚拟机栈, 本地方法栈

每条线程持有一份

伴随线程创建而创建, 销毁而销毁

方法的栈帧在指向完成后自动弹出栈释放掉对应的内存

## 方法区的GC

方法区的类信息如何被回收

### 类的生命周期

1.  加载 Loading
2.  链接 Linking
    1.  验证 内容是否满足《JVM规范》
    2.  准备 静态变量赋初值
    3.  解析 常量池中的符号引用替换为指向内存的直接引用
3.  初始化 Initialization
4.  使用 Using
5.  **卸载 Unloading**

### InstanceKlass对象的回收条件

1.  此类所有的实例对象都已经被回收, 在堆中不存在任何该类的实例对象以及子类对象

    ```java
    Object o = loader.loadClass("org.example.ExampleObject").newInstance();
    o = null; // 此行为对垃圾回收器来说就是该对象不被任何对象使用(当然有一个计数器)
    ```

    当然, 在一个作用域结束之后, 不需要显式地写`=null`, 垃圾回收器也认为对象已经无人使用

2.  加载该类的类加载器已经被回收

    -   但是, 我们的类都是由AppClassLoader加载, 这个加载器应该不会被回收才是

3.  该类对应的`java.lang.Class`对象不再任何地方被引用



### 方法区的回收场景



在开发中要出现回收InstanceKlass的情况很少出现

在OSGI和JSP的热部署应用场景中, 每个JSP文件对应一个唯一的类加载器,当JSP文件修改了, 就直接卸载这个JSP类加载器, 重新创建类加载器, 重新加载JSP文件, 实现热部署和资源的释放
