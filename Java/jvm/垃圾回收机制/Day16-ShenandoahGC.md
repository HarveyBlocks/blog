# ShenandoahGC

在G1源码上再开发

-   SheandoahGC在Region上的定义与G1一致
-   通过修改对象头的设计来完成并发转移过程的实现
-   JDK8和JDK11使用ShenandoahGC 1.0不够稳定可靠 , 后续版本使用2.0

## ShenandoahGC 1.0

### 前向指针

对象头前增加**前向指针**, 指向转移后的对象, 没有这个对象就指向自己

读取数据, 使用读前屏障, 用户如果拿到转移前对象(**前向指针没有指向自己, 而是指向了别的对象**), 执行转移

### GC状态

GC状态如果位0表示没有处在GC过程中, 不为0表示GC的各个阶段

写入数据, 使用写前屏障, 用户线程判断Mark Word(对象头中的标记字段)中的GC状态, 协助执行垃圾回收

例如转移阶段通过前向指针, 将数据写入新对象

### 缺点

-   增加前向指针, 对象内存空间占用大大增加
-   读屏障中加入复杂指令, 影响用户线程的效率

## ShenandoahGC 2.0

在转移阶段, Mark Word标记字段充当前向指针

在其他时候, Mark Word依旧是Mark Word

## 流程

1.  初始标记
    -   STW
    -   标记GC Root直接引用的对象
2.  并发标记
    -   遍历所有对象
    -   标记可以达到的所有对象是否存活
    -   **用户线程辅助标记**
3.  结束标记
    -   STW
    -   整理标记, 为下一阶段做准备
4.  并发转移
    -   将对象转移到新的区域中
5.  并发重映射
    -   将指向老对象的引用全部更改为新对象

### CAS

>   Compare And Swap 比较并交换

如果用户线程在转移时, GC线程也发现这个对象需要复制, 就会尝试写入前向指针

使用CAS, 只有一个线程能执行成功, 其他线程放弃转移操作
