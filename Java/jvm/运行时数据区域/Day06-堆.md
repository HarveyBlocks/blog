# 堆

>   heap

一般是Java程序中空间占用最大的一块区域

**创建的对象都存放再堆上**

栈上的局部变量表中, 可以存放堆上的对象引用

静态变量也可以存放堆对象的引用, 通过静态变量就可以实现线程之间的共享

## 管理

JVM将堆内存区域分为

-   used
    -   已使用的
-   total
    -   JVM已分配可用的
-   max
    -   JVM可分配的最大堆内存
    -   默认上限7G(时代真的变了啊)

Arthus查看

```shell
dashboard -i 刷新频率(ms)
```

只关注内存(不刷新)

```shell
memory
```

## 配置堆内存大小

-   默认Max是系统内存的1/4

    ```shell
    -Xmx16G
    ```

    -   必须大于2M

-   默认total是系统内存的1/64

    ```shell
    -Xms1G
    ```

    -   必须大于2M

Arthas中获取的Heap堆内存大小使用JMX技术获取

这种方式和垃圾回收器有关, 计算的是可以分配对象的内存, 而不是整个内存(GC不能回收底层Cpp产生的内存吧?)

建议将total设置成和max一样, 减少反复分配内存的过程

如果total和used差距很大, JVM会进行收缩(但不会收缩得比配置的小)

这么豪爽地配置total, 是因为企业中一台机子就只留给一个Java程序用了, 不用白不用

## 内存溢出

堆溢出 `OutOfMemoryError`

然而经过测试, 占用75%左右就会出现 `OutOfMemoryError`的报错, used≈total≈0.75max(total一开始配置得比max小得多的情况), 这是因为GC垃圾回收器的缘故
