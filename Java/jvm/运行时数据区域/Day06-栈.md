## JVM栈

使用了栈的数据结构, 每一个方法的调用使用一个栈帧(**Stack Frame**)来保存

常常有方法内调用方法的情况

1.  当一个方法被调用, 开始执行时, 方法栈帧入栈
    1.  方法内调用了一个方法, 该方法栈帧入栈
    2.  内部调用的方法结束, 该方法栈帧出栈
2.  当一个方法执行结束时, 方法栈帧出栈

↓此乃栈帧

## 栈帧组成

-   局部变量表
    -   运行过程中存放所有的局部变量
-   操作数栈
    -   执行指令过程中存放临时数据的一块区域
-   帧数据
    -   动态连接
    -   方法出口
    -   异常表

### `Nr`

 局部变量的编号, 出现的次序

### `起始PC` +`长度`

限制了局部变量的起效的长度

-   `起始PC 2` 对应字节码指令前面的`2`
-   `长度3` 表示起效三行字节码指令

### `序号`

-   对于非静态方法, this作为第一个参数位于变量表的最前面(指序号为0)

-   形式参数也是一个变量, 序号紧随this之后

-   栈帧中的局部变量表是一个数组, 数组中的每一个位置称为**槽slot**, long和double类型占2个槽, 其他类型占1个槽

    ![image-20240518171908071](../assets/Day06-%E6%A0%88/image-20240518171908071.png)

    ```java
    public static void test(){
        int i = 0;
        long j = 1;
    }
    ```

    

    ![image-20240518172633937](../assets/Day06-%E6%A0%88/image-20240518172633937.png)

    ```java
    public static void test(){
        int i = 0;
        long j = 1;
        int k = 1;
    }
    ```

    j占两个插槽, k的序号就为3了

-   为了节省空间,局部变量表中的槽是可以复用的, 一旦某个局部变量不再生效, 当前槽就可以再次被使用

    ```java
    public void test4(int k,int m){
        {
            // 作用域限定
            int a = 1;
            int b = 2;
        }
        {
            int c = 1;
        }
        int i = 0;
        long j = 1;
    }
    ```



## 操作数栈

帧栈中JVM在执行指令过程中用来存放中间数据的一块区域

在编译期就可以确定操作数栈的最大深度(用模拟的方式将代码走一遍), 从而在执行时正确分配内存大小

常常用来存放一些常量

```java
int a = 0;
```

1.  0放入操作数栈
2.  0出栈放入局部变量表a的位置

```java
int b = a + 2;
```

1.  2放入操作数栈
2.  去除a的值放入操作数栈
3.  计算操作数栈里的两个数的和
4.  取出这个和, 赋值给b

## 帧数据

### 动态链接

当前类的字节码指令引用了其他类的属性或方法时, 需要将符号引用(编号)转换成对应的运行时常量池中的内存地址

动态链接就保存了编号到运行时常量池的内存地址的映射关系



```class
getstatic #10 <java/lang/System>
```

`#10`是一片内存区域



### 方法出口

方法结束之后, 栈帧就会弹出栈

程序计数器会记录程序接下来执行的地址, 也就是指向新栈顶的方法

但此时程序计数器指向的字节码指令一定不是方法的开始, 但它由怎么知道刚刚那个方法结束之后该去往何方呢?

JVM的做法是, 在上一个栈帧中存放了外层方法的下一行字节码指令的地址

在方法出栈之前, 会将程序计数器应该指向的下一行字节码指令的地址交给程序计数器, 然后再出栈

### 异常表

如果代码中出现了异常的捕获, 编译器会把源代码编译成字节码的过程中, 生成一张异常表

其中包含了异常捕获的生效范围和异常发生后跳转到的字节码指令位置

## 栈内存溢出

会溢出

栈溢出`StcakOverflowError: heap space`

栈有一个默认的上限大小, 取决于操作系统和计算机体系结构

-   Linux_x86(64位): 1MB
-   Linux_ppc: 2MB
-   BSD_x86: 1MB
-   Solaris_64位: 1MB
-   Window: 基于操作系统默认值

虚拟机参数设置栈帧的上限

```shell
-Xss8M
```

-   缺省 字节, 必须是1024的倍数
-   K
-   k 同K
-   M
-   m 同M
-   G
-   g 同G

也可以使用`-XX:ThreadStackSize`配置堆栈大小

```shell
-XX:ThreadStackSize=1024
```

HotSpot对栈的最大值和最小值有要求

Windows_x86下的JDK8最小180K, 最大1024M, 超出就会做出调整

## 本地方法栈

再Hotspot中, JVM栈和本地方法栈实现上使用了同一个栈空间

本地方法栈会在栈内存上生成一个栈帧, 临时保存方法的参数

方便出现异常时也把本地方法的栈信息打印出来
