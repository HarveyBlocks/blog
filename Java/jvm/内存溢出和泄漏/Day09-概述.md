# 内存溢出和内存泄漏

## 内存泄漏

>   Memory Leak

如果不再使用一个对象, 该对象依然在GC Root的引用链上而无法被回收的情况

内存泄漏绝大多数情况由**堆内存泄漏**引起

就是你不会再用到了, 但是你忘记释放引用了, 例如List里面的内容不主动删除是不会释放的



### 危害

如果数据产生的很快, 每次数据都很多很大, 内存泄漏可能像滚雪球一样, 最终导致**内存溢出**(内存溢出的产生原因不只是内存泄漏)

### 产生场景

我不理解, 照现在的MVC的设计方式, 数据都用局部变量存储, 方法结束都被释放, 每次都能保证将对象释放啊

每次都是一个线程对应一个请求, 字段也不适合做数据的存储啊

字段存数据要不就是阻塞队列存任务

Http也是短链接

除非一次请求就能有大量的数据





分布式任务调度系统如Elastic-job, Quartz等进行任务调度(定时任务)时, 被调度的Java应用出现了内存泄漏, 多次调度后最终导致内存溢出

## 并发请求问题

并发量非常高, 完全由可能出现回收掉前面一个请求的内存, 马上来了是个请求带来了对应的十倍内存

1.  同一时间的并发量很大(Tomcat对并发请求量有上限200个)
    -   限流, 削峰
2.  每一次请求的数据量很大
    -   分页
3.  每一次请求的时间很长
    -   批量操作
