# final

## final变量不可写原理

在final变量初次赋值之后加入写屏障

1.  写屏障保证数据同步到主存

2.  写屏障保证其之前不会发生指令重排序

    创建final变量需要先开辟空间再赋值, 这两步中间不能中断了

## final的变量的读

C中有define, 其具有在编译之前就将define的代码拷贝到代码中的作用, 但是这就导致了多次实例化一个对象

final修饰的变量(不论是不是静态的), Java在编译成字节码的时候, 对于基本数据类型, 会进行拷贝, 而不是调用(甚至会进行一些简单的运算之后进行拷贝, 例如运算都是基于的常量的, 例如`final int a = Short.Max+1; ` 这种就会拷贝); 

值较小复制到方法栈中, 值较大(Short.MAX)复制到类的常量池中

对于引用数据类型, 会在类创建的时候进行实例化一个对话然后再调用引用
