# 悲观锁和乐观锁

-   悲观锁认为时刻可能有线程来争夺共享资源

-   乐观锁认为, 资源被争夺不是一件很常见的事情, 只需要在发现资源被争夺之后, 放弃这次操作, 然后循环重试即可

    由于是基于不间断重试, 乐观锁的使用场景, 线程数不应该超过核心数, 否则没有意义

## CAS

>   Compare and Swep

我一直有一个误解:

我一直认为CAS是一种算法, 是一种编程模式或范式

然而, CAS是CPU层面的指令, 将一次读写的操作集成为一个指令, 在CPU指令层保证了原子性,

因此才不用考虑内存模型的三个问题

### 效率

因为不用像悲观锁那样创建管程, 阻塞和上下文切换, 

只要重试次数不多, 一般是要比悲观锁要快的

-   无锁: 39.3139 ms
-   有悲观锁(方法上): 41.1446 ms
-   有悲观锁(方法内): 41.5423 ms
-   有悲观锁(ReentrantLock): 42.91755 ms
-   有乐观锁(1000线程高并发): 56.8240 ms
-   有悲观锁(方法上, 10线程低并发): 16.2152 ms
-   有悲观锁(方法内, 10线程低并发): 16.4359 ms
-   有乐观锁(10线程低并发): 17.1030 ms

### 使用

CAS在Java的体现就是各Atom类及Unsafe类
