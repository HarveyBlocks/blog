# 共享问题

## 线程安全问题

对线程间共享的资源进行写操作时

多线程上下文切换引起了指令交错, 进而引发线程安全问题

##概念



### 临界区

一段代码内如果存在对**共享资源**的多线程**读写操作**, 这段代码为**临界区**



```java
Thread t1 = new Thread(() -> {
    for (int i = 0; i < 100; i++) {
        // 临界区↓
        num++;
        // 临界区↑
    }
}, "t1");
```

###竞态条件

>   Race Condition

多线程再临界区内执行, 由于代码的**执行序列不同**而导致结果无法预测, 称为**竞态条件**

## 线程安全分析

在资源被共享且同时有读写的情况下才会有线程安全问题

- 成员变量和静态变量

    - 被共享且, 同时有读写的情况下有线程安全问题

- 局部变量

    - 局部变量本身是线程安全的

    - 局部变量的成员没有逃离方法的作用范围, 则是线程安全的

        ```java
        public void decrement() {
            int value = 1;
            value--;
        }
        ```

        `decrement()`被多线程调用, value是否存在线程安全问题?

        `decrement()`被调用, 就享有一份自己的栈帧, 栈帧在方法栈中, 局部变量在栈帧中, 每个线程有自己独立的栈

        也就是说, `decrement()` 被多线程调用, 其局部变量value是没有被共享的

        所有不存在线程安全问题

    - 局部变量的成员逃离了方法作用范围, 则不是线程安全的

        ```cpp
        public void method(List<Integer> list) {
            new Thread(()->{
                // 实际上进入了匿名内部类Runnable的子实现类, 是
                list.remove(0);
            }).start;
        }
        ```

        

        

## 外星方法

抽象方法的参数由父类提供, 方法体由子类实现

父类提供的方法参数可能被子类的实现放在多线程中被共享

导致线程不安全

此谓之 **外星方法**
