# 用况图

- 用于描述系统需求, 准确地描述用户需求中的功能需求, 形成功能规格说明
- 用于对系统的功能功能以及与系统进行交互的外部事务建模
  1. 找出与系统交互的外部事物
  2. 说明他们如何与系统交互, 利于对系统进行探讨和理解
  3. 用况图是对需求的规范化描述, 是进行OOA的基础
- **系统边界** 找出在系统边界外与系统交互的事物, 然后从事物与系统进行交互的角度, 通过用况来描述这些事务怎样使用系统, 以及系统向他们提供什么功能



## 系统边界

将系统看作黑箱, 对外部显示世界发挥什么作用, 描述它的外部可见行为

系统特指计算机软件系统

系统边界是一个系统所包含的所有的系统成分与系统以外各种事物的分界线

系统是有一条边界包围起来的未知空间, 系统只通过边界上的有限个接口与外部的系统使用者

1. 系统-系统使用者



1. 系统成分, 商品抽象为商品类, 在系统内
2. 收款员, 算作系统外的, 系统使用者, 系统内设立收款员类, 系统不关注收款员信息
3. 但是这个系统需要登录, 有记录收款员信息, 有收款员类, 这种, 可以同时存在 系统内部的"类" 和系统内部外的 "参与者"
4. 有些事物即使属于问题域, 也和系统责任没有关系, 如保安, 和超市有关, 和超市商品销售系统无关

## 参与者

> actir

与系统交互的事物(人/调用系统接口的另一系统)

一个用户可以扮演不同的参与者, 一个参与者可以由不同的人来扮演
