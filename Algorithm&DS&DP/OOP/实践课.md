# 面向商家的羽毛球专卖系统

- 买家
- 员工(系统的使用者)

## 分模块

### 商品管理

- 上架商品
    - 卖家录入商品详细信息-> 设定价格与库存 -> 发布。
- 商品信息 更新
- 进货渠道
- 账单管理
    - 进货价
    - 出货价
    - 变化曲线

### 订单交易管理

- 订单
    - 卖家查看新订单 -> 审核订单详情（商品、价格、收货信息、买家要求）-> 确认订单有效性
- 发货
    - 卖家填写物流信息 -> 系统更新订单状态为“已发货”并通知买家 -> 集成物流接口实现轨迹跟踪。
- 支付

### 售后

- 退货
    - 卖家受理用户的退货/退款申请 -> 审核售后原因与凭证 -> 做出处理决定（同意/拒绝）-> 若同意，执行退款操作并更新库存。
- 保修, 员工KPI
- 保修预约( TODO list, 有预约过来就会写入这个TODO list, 员工自己领取任务)

### 客户关系管理

- 客户信息管理
    - 生成客户档案。卖家可查看客户资料、交易历史、客单价等，并为其添加标签或备注。
- 沟通过程中可能会出现客户想要"售后预约", 则进入售后模块
- 买家 VIP 与折扣优惠

### 系统管理与安全

- 员工
    - 管理员为不同职责的员工创建账号，并分配不同的操作权限（如：只读订单、仅限商品管理等）
    - 前台
    - 店长(管理员)
    - 进货
    - 修理
- 工资分发. 职位, 权限
- 内部群, 员工交流群, 通讯系统, 广播, 私聊(即使通讯 IM)

### 员工身份管理

#### 注册账号

权限分配, 权限如下:

- 前台
- 店长
- 进货
- 修理

系统需依据其角色自动限定可操作的功能范围（例如，进货员不能查看财务报表）

| Tittle   | Description                                                  |
| -------- | ------------------------------------------------------------ |
| 用况名   | 注册账号                                                     |
| 描述     | 店长或授权管理员在系统中为新员工注册账号的过程，包括输入员工基本信息、分配权限角色（前台、店长、进货、修理），并确保系统根据角色自动限制可操作的功能范围（例如，进货员不能访问财务报表模块）。注册成功后，员工账号被激活，并可在权限范围内使用系统。 |
| 参与者   | 店长（或具有管理员权限的员工）                               |
| 包含     | 身份与权限管理                                               |
| 扩展     | 无                                                           |
| 泛化     | 无                                                           |
| 前置条件 | 店长必须已成功登录系统，并具有“员工管理”模块的访问权限。<br>系统必须处于正常运行状态，数据库连接可用。 <br/>新员工的基本信息（如姓名、联系方式）已由店长收集完毕。<br/>权限角色列表（前台、店长、进货、修理）已在系统中预定义且可用。 |
| 细节     | **店长登录系统**：店长使用自己的账号登录系统，系统验证其权限（店长角色可访问员工管理模块）。 <br/>**进入员工管理模块**：店长在系统主菜单中选择“员工管理”选项，系统显示员工列表页面。<br/> **发起注册**：店长点击“注册新员工”按钮，系统弹出注册表单。 <br/>**填写员工信息**：  表单包括字段：员工姓名、员工编号（系统自动生成或手动输入）、联系电话、邮箱、用户名（用于登录）、初始密码（系统生成默认密码，如“123456”，并要求首次登录后修改）。 所有字段均为必填，系统实时验证格式（如邮箱格式、用户名长度）。 <br/>**分配权限角色**：  店长从下拉列表中选择一个权限角色：前台、店长、进货或修理。 系统根据角色自动映射可操作的功能范围：  <br/>**前台**：允许访问销售模块（如商品销售、会员管理）、订单查询，但禁止访问库存管理、财务报表和修理记录。<br/>**店长**：允许访问所有模块，包括销售、库存、财务报表、员工管理和修理记录。 <br/>**进货**：允许访问库存管理模块（如商品入库、采购订单）、供应商信息，但禁止访问销售模块、财务报表和修理记录。 <br/>**修理**：允许访问修理服务模块（如修理订单管理、器材维护记录），但禁止访问销售模块、库存管理和财务报表。 系统内部维护一个权限矩阵，角色选择后自动应用限制，无需手动配置。 <br/>**提交注册**：店长点击“提交”按钮，系统执行以下操作：  验证用户名是否唯一（如与现有员工重复，则报错）。 检查所有必填字段是否完整。 如果验证通过，系统保存员工信息到数据库，并分配角色权限。 系统生成员工账号，状态为“激活”。<br> **确认注册**：系统显示“注册成功”消息，并返回员工列表页面，新员工账号显示在列表中。 |
| 后置条件 | 新员工账号被成功创建并存储在系统中，状态为“激活”。 <br/>权限角色已分配，系统自动限制该员工可访问的功能模块（例如，进货员登录后只能看到库存管理相关菜单）。<br/> 系统记录操作日志，包括注册时间、店长操作者、新员工角色。<br/>新员工可使用用户名和初始密码登录系统，并在权限范围内操作。 |
| 例外     | 参数填写错误(参数不足or内容错误)<br>操作者权限不足           |
| 注释     | 权限分配是自动的，基于角色预设的功能范围，无需店长手动配置具体权限。这减少了人为错误，确保安全。 <br/>在羽毛球专卖系统中，权限设计应贴合业务：例如，“修理”角色专注于羽毛球拍修理服务，不涉及销售或财务； “进货”角色关注库存采购，避免数据泄露。 <br/>初始密码应强制员工首次登录后修改，以增强安全性。 <br/> |

#### 排班

- 店长排班
- 店长需要快速知道当前是谁在值班，以便联系处理紧急事务

| Tittle   | Description                                                  |
| -------- | ------------------------------------------------------------ |
| 用况名   | 排班                                                         |
| 描述     | 店长通过系统管理员工的排班表，包括添加、修改和删除排班条目，并实时查看当前值班员工信息（如姓名和联系方式），以便快速联系处理紧急事务。 |
| 参与者   | 店长（主要参与者，负责排班和查看当前值班）                   |
| 包含     | **身份与权限管理**：排班用况必须包含系统中已存在的“认证”用况，以验证店长身份。店长在访问排班功能前，需先通过登录验证。<br>**检索员工信息**：排班用况包含系统中已存在的“检索员工信息”用况，以获取当前员工列表（包括姓名、联系方式等），用于选择员工进行排班。 |
| 扩展     | 无                                                           |
| 泛化     | 无                                                           |
| 前置条件 | 店长已通过系统认证（登录成功）。<br>系统中有完整的员工信息库（员工姓名、联系方式等均可用）。 <br/>系统时间与营业时间同步，准确无误。 <br/>排班表数据可正常访问和修改。 |
| 细节     | **访问排班界面**：店长登录系统后，选择“排班管理”。  排班表视图：以日历或表格形式展示当前排班，包括员工姓名、排班日期、时间段（如9:00-12:00、13:00-18:00等）。 当前值班员工栏：在界面顶部或侧边固定显示，基于系统时间自动更新当前值班员工姓名和联系方式（如电话号），店长无需额外操作即可快速查看。 <br/>**排班操作**：  <br/>**添加排班**：店长点击“添加排班”按钮，系统弹出表单，店长从员工下拉列表（源自系统员工信息）选择员工，使用日期选择器设置排班日期，并通过时间下拉菜单选择时间段。系统自动检查排班冲突（如同一个员工在同一时间段内已排班），如冲突则显示错误提示，否则保存新排班。 <br/>**修改排班**：店长在排班表中选择现有排班条目，点击“修改”按钮，系统允许编辑员工、日期或时间段。系统再次验证冲突，若无冲突则更新。 <br/>**删除排班**：店长选择排班条目，点击“删除”按钮，系统要求确认，确认后立即移除该排班。 <br/>**查看当前值班**：系统实时监控时间，当店长打开排班界面或主页时，当前值班员工信息自动显示在醒目位置。如果当前时间无排班，系统显示“无值班员工”。 <br/>**保存与更新**：店长完成操作后，点击“保存”按钮，系统更新排班数据。当前值班信息随排班变化实时调整。 |
| 后置条件 | 排班表数据成功更新，反映最新的添加、修改或删除操作。 <br>当前值班员工信息准确无误，基于最新排班表显示。 <br/>系统数据保持一致，无损坏或丢失。 |
| 例外     | **员工不可用**：如果选择的员工不存在或已离职，系统显示错误：“员工不可用，请检查员工列表”。<br>**排班冲突**：如果排班时间与现有排班重叠，系统提示：“排班冲突，请调整时间段”。<br/>**无值班员工**：如果当前时间无排班，系统显示：“当前无值班员工”。 <br/> |

### 工资分发

#### 绩效数据聚合

能够自动统计每位员工的核心业务数据

- 前台员工的销售额、办理会员数
- 修拍师的接单量、完工率
- 进货员的采购单处理量

| Tittle   | Description                                                  |
| -------- | ------------------------------------------------------------ |
| 用况名   | 绩效数据聚合                                                 |
| 描述     | 自动统计不同角色员工的核心业务数据（关键绩效指标，KPI），包括前台员工的销售额和办理会员数、修拍师的接单量和完工率、进货员的采购单处理量。统计结果用于管理者评估员工绩效 |
| 参与者   | 店长——触发统计过程或查看结果                                 |
| 包含     | 员工信息管理                                                 |
| 扩展     | 无                                                           |
| 泛化     | 无                                                           |
| 前置条件 | 系统管理员已成功登录系统，并具有员工管理模块的访问权限。<br> 系统已存储完整的员工基本信息<br> 系统已记录相关业务数据<br> 业务数据的时间戳完整，允许按时间段筛选。<br> |
| 细节     | **前台员工**：<br>                     销售额：从销售订单表中，统计该员工在指定时间段内处理的所有订单的总金额（货币单位）。仅计入状态为“已完成”的订单。<br>                      办理会员数：从会员注册表中，统计该员工在指定时间段内成功注册的新会员数量。仅计入状态为“有效”的注册。<br> **修拍师**：<br>                      接单量：从修拍订单表中，统计该员工在指定时间段内接收的订单数量（状态为“已接收”或“进行中”）。<br>                      完工率：计算指定时间段内该员工完成的修拍订单数量（状态为“已完成”）与接单量的比率。公式：完工率 = (完成订单数 / 接单量) * 100%。<br> **进货员**：<br>                      采购单处理量：从采购订单表中，统计该员工在指定时间段内处理的采购订单数量。包括订单状态为“已提交”、“已审核”或“已完成”的订单，每个订单只计数一次（基于员工ID关联）<br> |
| 后置条件 | 系统成功计算并存储绩效统计结果（临时或持久化），可供管理员查看<br>绩效数据更新至最新状态，反映指定时间段的业务情况 |
| 例外     | 如果指定时间段内没有业务数据（如无销售订单或修拍订单），系统在报告中显示KPI值为零或提示“无数据” |
| 注释     | 仅支持前台员工、修拍师和进货员角色；如需添加新角色，需修改用况细节 |

### 内部交流群

#### 即时消息与群组

支持员工之间、跨部门的点对点和群组实时文字通讯。

#### 任务导向通讯(算作售后)

支持在通讯中快速创建或引用一个具体的业务任务

- 在群聊中针对 “某型号球拍缺货” 问题，可直接创建一条“采购任务”并指派给进货员
- 有顾客预约了球拍穿线，前台可以创建一个“为顾客YYY穿线”的任务，指派给修拍师，并设定预约时间
- 一个简单的任务列表，包含任务内容、负责人、截止日期和状态（待处理/进行中/已完成）
