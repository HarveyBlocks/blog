# 订单交易管理模块用况分析

## 用况1：审核新订单

**用况简介**：此用况是订单生命周期的起点，通过人工审核确保订单的准确性与可执行性。对于羽毛球专卖店，重点在于确认特殊服务要求（如穿线）的可行性，核对商品库存，避免发货错误和客户投诉。

| 属性 | 描述 |
|------|------|
| **用况名** | 审核新订单 |
| **描述** | 卖家逐项审核新订单中的商品信息、价格明细、收货地址及买家特殊要求，综合判断订单有效性，决定是否确认订单或取消订单。 |
| **参与者** | 卖家（具有订单处理权限的店员或店长） |
| **包含** | 检查库存可用性<br>验证订单完整性 |
| **扩展** | 1. 如果库存不足：执行"生成采购建议"用况<br>2. 如果地址无法配送：执行"联系买家修改地址"用况<br>3. 如果服务要求无法满足：执行"协商服务方案"用况 |
| **泛化** | 订单审核（父用况）<br>├── 普通商品订单审核<br>└── 定制服务订单审核（需要额外评估服务可行性） |
| **前置条件** | 1. 卖家已成功登录系统<br>2. 系统中存在状态为"待审核"的新订单<br>3. 商品库存数据可用 |
| **细节** | 1. **查看待审核订单列表**：系统展示所有"待审核"订单，显示订单号、下单时间、买家信息、订单总额<br>2. **审核订单详情**：卖家点击订单进入详情页，仔细核对：<br>   - **商品信息**：商品名称（如"尤尼克斯天斧100ZZ"）、规格型号、数量、单价<br>   - **价格明细**：商品总价、运费、优惠折扣、实付金额<br>   - **收货信息**：收货人姓名、联系电话、详细配送地址<br>   - **服务要求字段**：专门显示买家特殊要求，如："球拍穿26磅BG65线"、"手胶换成白色"、"开发票抬头：XX公司"<br>3. **库存与可行性评估**：<br>   - 系统自动检查商品库存，库存紧张时高亮显示<br>   - 卖家根据服务要求评估执行能力（如特定穿线要求是否可完成）<br>4. **审核决策**：<br>   - **确认订单**：点击"审核通过"，订单状态变为"待处理"<br>   - **取消订单**：选择取消原因："库存不足"、"地址超区"、"无法满足服务要求"等 |
| **后置条件** | 1. 订单状态从"待审核"变更为"待处理"或"已取消"<br>2. 系统记录审核操作人和时间<br>3. 审核通过的订单，系统预留相应库存 |
| **例外** | 1. 审核过程中商品库存变为0，系统阻止审核通过并提示<br>2. 买家要求无法满足（如要求的穿线磅数超出范围）<br>3. 收货地址不完整或无法配送 |
| **注释** | 服务要求字段是羽毛球专卖业务的核心，必须清晰明确，便于后续执行 |

## 用况2：执行订单发货

**用况简介**：此用况负责将已确认的订单转化为实际发货状态。重点在于准确记录物流信息，并通过可行的方式（短信/邮件）通知买家，建立物流跟踪的基础。

| 属性 | 描述 |
|------|------|
| **用况名** | 执行订单发货 |
| **描述** | 卖家对已处理完毕的订单，手动录入物流公司及运单号，系统更新订单状态并通过短信或邮件通知买家发货信息。 |
| **参与者** | 卖家（具有发货权限的店员）<br>短信网关（次要参与者） |
| **包含** | 验证运单号格式<br>更新库存数量 |
| **扩展** | 1. 如果商品缺货：执行"部分发货"用况<br>2. 如果物流公司不支持：执行"更换物流公司"用况<br>3. 如果通知发送失败：执行"手动通知买家"用况 |
| **泛化** | 订单发货（父用况）<br>├── 普通快递发货<br>├── 加急快递发货<br>└── 到店自提发货 |
| **前置条件** | 1. 卖家已成功登录系统<br>2. 目标订单状态为"待发货"<br>3. 商品已实际打包并获取物流单号 |
| **细节** | 1. **进入待发货列表**：卖家在订单管理中筛选"待发货"订单<br>2. **填写物流信息**：选择订单点击"发货"，填写：<br>   - **物流公司**：从预设列表选择（顺丰、中通、圆通等）<br>   - **运单号**：手动输入，系统进行基础格式校验<br>3. **确认发货**：点击"确认发货"，系统执行：<br>   - 更新订单状态为"已发货"<br>   - 记录发货时间、操作人、物流信息<br>   - 发送通知：通过短信或邮件发送："【XX羽球】您的订单（订单号XXX）已发货，快递：XXX，单号：XXX"<br>4. **提供查询支持**：订单详情页提供各快递公司官网查询链接 |
| **后置条件** | 1. 订单状态更新为"已发货"<br>2. 物流信息准确记录<br>3. 系统已尝试发送发货通知<br>4. 对应商品库存数量减少 |
| **例外** | 1. 运单号格式错误，系统提示重新输入<br>2. 通知发送失败，系统记录并提示卖家<br>3. 发货时发现商品实际缺货 |
| **注释** | 采用"手动录入+查询链接"方案，成本低且实用，适合中小型专卖店 |

## 用况3：处理支付与退款

**用况简介**：此用况管理订单的资金流处理，重点在于建立规范化的退款流程记录。通过完整的退款申请、审核、执行记录，确保财务清晰，便于处理售后纠纷。

| 属性 | 描述 |
|------|------|
| **用况名** | 处理支付与退款 |
| **描述** | 系统记录订单支付状态，在需要退款时，卖家记录退款申请、审核退款理由、执行退款操作并记录全过程。 |
| **参与者** | 卖家（主参与者）、买家（发起退款申请）<br>财务系统（次要参与者） |
| **包含** | 计算可退金额<br>生成退款流水号<br>更新财务记录 |
| **扩展** | 1. 如果部分退款：执行"计算部分退款金额"用况<br>2. 如果退货退款：执行"处理退货流程"用况<br>3. 如果争议退款：执行"升级处理争议"用况 |
| **泛化** | 退款处理（父用况）<br>├── 全额退款<br>├── 部分退款<br>└── 换货处理 |
| **前置条件** | 1. 卖家已成功登录系统<br>2. 目标订单支付状态为"已支付"<br>3. 卖家具有退款操作权限 |
| **细节** | 1. **查看支付信息**：订单详情页显示支付方式、金额、时间、状态<br>2. **受理退款申请**：<br>   - **记录申请信息**：买家通过电话/微信申请后，卖家点击"受理退款"，填写：申请人、申请时间、退款原因（如"拍框瑕疵"、"穿线错误"）、要求金额<br>   - **上传凭证**：支持上传问题照片、聊天记录等证据<br>3. **审核与执行**：<br>   - **卖家审核**：根据退款原因和凭证决定是否同意<br>   - **执行退款**：输入实际退款金额、选择退款方式（原路退回/线下转账）、添加处理备注<br>   - **更新状态**：系统更新支付状态为"已退款"，记录完整退款流水<br>4. **通知买家**：退款完成后，卖家手动通知买家查收 |
| **后置条件** | 1. 订单支付状态和退款金额更新<br>2. 系统生成完整的退款记录，包含申请、审核、执行全过程<br>3. 财务记录同步更新<br>4. 库存相应调整（如涉及退货） |
| **例外** | 1. 退款金额超过可退金额，系统阻止操作<br>2. 原支付通道退款失败，需转为线下处理<br>3. 退款申请理由不充分，卖家拒绝退款 |
| **注释** | 重点在于建立完整可追溯的退款记录，为财务对账和纠纷处理提供依据 |

## 业务特性说明

### 羽毛球专卖业务在订单管理中的体现
1. **服务要求标准化**：在订单中设立专门的服务要求字段，规范化记录穿线磅数、线材类型、手胶更换等特殊需求
2. **高价值商品处理**：对高单价球拍订单增加审核环节，必要时进行二次确认，降低经营风险
3. **器材专业性体现**：在商品信息中完整记录球拍参数（重量、平衡点、穿线方式），便于核对和售后服务

### 用况关系说明
1. **包含关系**：标识了必须执行的子功能，如库存检查、金额计算等
2. **扩展关系**：处理异常情况和可选流程，增强系统健壮性
3. **泛化关系**：体现不同类型订单处理的共性特征，支持业务扩展
