# SDS

>   Simple Dynamic String 简单动态字符串

## C字符串的弊端

-   获取字符串的长度需要计算
-   非二进制安全(遇到`\0`就停止, 和想的不一样)
    -   对于ASCII字符说不定没啥问题
    -   对于的图片等二进制文件, 问题就很大
-   不可修改(存在常量池)

## 简单动态字符串

-   Key和Value都是这种字符串

```c
struct __attribute__ ((__packed__)) sdshdr8 {
    unit8_t len; /*buf 已保存的字符串字节数, 不包含结束标示*/
    /*unit8_t = unsigned int 8 bytes*/
    unit8_t alloc; /*buf 申请总字节数, 不包含结束标示, sdshdr8是1, sdshdr16是2,sdshdr32是3, sdshdr64是4*/
    unsigned char flags; /*不同SDS的头类型, 用来控制SDS头大小*/
    char buf[];
}
```

Redis的key: `name`

```c
{
	len: 4,
	alloc: 4,
	flags: 1, 
	buf = {
		'n','a','m','e','\0' /*\0是为了和C做兼容*/
	}
}
```

### 动态扩容

假如需要给SDS追加一段字符串, 会首先申请新的内存空间

- 如果扩展后的字符串**小于 1M**, 则新空间为**扩展后字符串长度的两倍+1(`\0`)**

- 如果扩展后的字符串**大于 1M**,则新空间为**拓展后的字符串长度+1M+1.**

- 此称为**内存预分配**

    - 为什么要预分配?

        Linux不能直接向硬件申请内存

        申请内存只能从**用户态**切换到**内核态**

        这样会造成不可避免的内存损耗(非常消耗资源)

        所以提早取申请一下

### 优势

1.  不用计算字符串长度
2.  支持动态扩容
3.  减少内存分配次数
4.  二进制安全
