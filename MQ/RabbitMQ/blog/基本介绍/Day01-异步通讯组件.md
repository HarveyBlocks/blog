# 异步通讯

##异步通讯和同步通讯

同步通讯

-   实时
-   A 发出信息, B 马上收到
-   利于单线

异步通讯

-   时不时地看看消息
-   时效性较同步通讯差
-   利于多线操作( 并发能力强, 分布式 )

##同步通讯的不利

###纵向拓展阻塞等待式

OpenFein, 一种同步通讯, 向另一服务发起通讯后, 需要一直等着对方响应(阻塞)

### 级联导致失去高可用

前面的业务执行失败了, 后面的业务无法执行

## 异步调用的角色

-   消息的发送者
    -   原来的调用方
    -   投递消息的人
-   消息代理**Broker**
    -   管理, 暂存, 转发消息
    -   中间件
-   消息接收者
    -   原来的服务提供方
    -   接收和处理消息的人

## 使用消息代理流程

1.  完成必须同步调用的逻辑
    -   例如完成用户校验后才能做交易
2.  在**请求交易时**采用从消息代理**广播**的方式
3.  完成交易服务
4.  其他可以异步的服务(如短信服务和积分服务)**监听消息代理**
5.  完成交易服务后其他异步服务监听到信息
6.  其他异步服务开始执行异步操作

##异步调用

###优势

-   接触耦合, 拓展性强
-   无需等待, 性能好
-   故障隔离
-   缓存消息, 流量可以被**削峰填谷**
    -   消息代理作为中间件, 也有减轻服务器压力的效果
    -   其和连接池和线程池同样具有队列式的结构

### 缺陷

-   不能立刻得到结果
-   不知道对方成没成功
-   业务安全完全依赖于Broker的可靠性
