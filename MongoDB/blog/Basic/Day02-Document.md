# Document

一组键值(key-value)对(即 BSON)

1. 文档中的键/值对是有序的。
2. MongoDB**区分类型**和**大小敏感**
3. MongoDB的文档不能有重复的键
4. 文档的键是字符串。除了少数例外情况，键可以使用任意UTF-8字符。

## 文档结构

由成对的字段和字段值组成

字段值可以是任何一种 BSON类型，包括其他文档、数组和文档数组

```js
var mydoc = {
               _id: ObjectId("5099803df3f4948bd2f98391"),
               name: { first: "Alan", last: "Turing" },
               birth: new Date('Jun 23, 1912'),
               death: new Date('Jun 07, 1954'),
               contribs: [ "Turing machine", "Turing test", "Turingery" ],
               views : Long(1250000)
            }
```



### 字段名称

string类型

文档键命名规范：

- 键值必须唯一
- 键不能含有`\0` (空字符)。这个字符用来表示键的结尾。
- `.`和`$`有特别的意义，只有在特定环境下才能使用。
- [建议]以下划线`_`开头的键是保留的

#### 文档限制

- 文档大小限制
  - 一个BSOM文档大小上限16MB
  - 提供 **GridFS API** 协助存储超过最大大小的文档
- 字段顺序
  - BSON文档的字段(键)为有序字段
  - `{a: 1, b: 1}` 不等于 `{b: 1, a: 1}`
  - 查询引擎为了提高查询效率, **可能会**在查询处理过程中对字段重新排序
  - 处理一些投影操作(`$project`, `$addField`, `$set`, `$unset`)时, **可能会**对字段重排序
  - 重排序可能发生在中间结果以及最终结果中
  - `_id` 字段始终是文档中的第一个字段。
  - 一般情况下MongoDB会保留文档字段的写入顺序
  - `$rename`更新字段的操作可能引发字段重排序
- `_id` 字段
  - 如果插入的文档省略了 `_id`字段，则自动生成`ObjectId`
  - `upsert`(存在则更新, 不存在则插入)操作遵循上一条插入规则
  - **时间序列集合** 中，文档不需要`_id`字段
  - `_id` 字段始终是文档中的第一个字段。如果不是, MongoDB将其移到开头
  - `_id`可以是任意类型, 数组、正则表达式或undefined除外
  - 如果是应用程序生成的UUID作为ID, 建议使用BinData进行存储
